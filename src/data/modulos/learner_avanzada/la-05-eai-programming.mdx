## EAI Programming: Handling Subject and Header Lines with UTF-8/Non-ASCII Characters

When handling subject lines with UTF-8/non-ASCII characters in EAI programming, it's important to ensure proper encoding and decoding. 

The following are some considerations:

<div class="info-card">

<details>
<summary>Character Encoding:</summary>

Ensure that the subject and header lines support the necessary character encoding, typically UTF-8, to handle non-ASCII characters. Encode the subject and header lines appropriately using the chosen character encoding to represent the non-ASCII characters correctly.

</details>

<details>
<summary>MIME Encoded-Word Syntax:</summary>

To represent non-ASCII characters in the subject and header lines, utilize the MIME encoded-word syntax. The MIME encoded-word syntax has the following general structure: `=?charset?encoding?encoded-text?=`
  - `charset`: Specifies the character set of the encoded text.
  - `encoding`: Specifies the encoding method used for the text. Common values are "Q" for Quoted-Printable and "B" for Base64.
  - `encoded-text`: Represents the actual encoded text.

<details>
<summary>Example1: MIME Encoded-Word Syntax Representing the Arabic Word “Marhaba”:</summary>

=?UTF-8?Q?=D9=85=D8=B1=D8=AD=D8=A8=D8=A7?=
In this example:
- UTF-8 is the character set.
- Q indicates Quoted-Printable encoding.
- =D9=85=D8=B1=D8=AD=D8=A8=D8=A7 is the Quoted-Printable encoded representation of the Arabic greeting word ""مرحبا" in UTF-8. Each non-ASCII character is represented by an equal sign "=" followed by two hexadecimal digits.

</details>

</details>

<details>
<summary>Subject and Header Lines Length:</summary>

Be aware that using non-ASCII characters in the subject and header lines may affect the length of the subject line.
Some characters, especially certain non-ASCII characters, may consume more than one byte or character space, potentially impacting the overall length limitations imposed by email protocols or email clients.

</details>

<details>
<summary>Encoding the Subject and Header Lines:</summary>

Before sending an email, encode the subject and header lines using the MIME encoded-word syntax. This includes converting any non-ASCII characters into their corresponding encoded form. 

Depending on the programming language or email library you are using, there may be built-in functions or methods available to handle this encoding. Alternatively, you can manually implement the encoding process using the MIME encoded-word syntax.

</details>

<details>

import javax.mail.*;

import javax.mail.internet.MimeBodyPart;
import javax.mail.internet.MimeMessage;
import javax.mail.internet.MimeMultipart;
import javax.mail.internet.MimeUtility;
import java.io.UnsupportedEncodingException;
import java.util.Properties;

public class EAIExample {
    public static void main(String[] args) {
        // Define sender and recipient email addresses
        String senderEmail = "your_sender_email@example.com"; // Replace with your sender's email address
        String recipientEmail = "recipient_email@example.com"; // Replace with the recipient's email address
        // Create a Properties object to hold the SMTP server details
        Properties props = new Properties();
        props.put("mail.smtp.host", "your_smtp_server.com"); // Replace with your SMTP server address
        props.put("mail.smtp.port", "587"); // Replace with the appropriate port
        props.put("mail.smtp.auth", "true");
        props.put("mail.smtp.starttls.enable", "true");

        Session session = Session.getInstance(props, new Authenticator() {
            protected PasswordAuthentication getPasswordAuthentication() {
                return new PasswordAuthentication("your_smtp_username", "your_smtp_password");
                // Replace with your SMTP username and password
            }
        });

        try {
            // Create a new MimeMessage object
            MimeMessage message = new MimeMessage(session);
            // Set the sender, recipient, and subject of the email
            message.setFrom(new InternetAddress(senderEmail));
            message.setRecipient(Message.RecipientType.TO, new InternetAddress(recipientEmail));
            message.setSubject("Internationalized Email Body Text");

            // Create a new MimeBodyPart object and set the content of the email
            MimeBodyPart bodyPart = new MimeBodyPart();
            String messageText = "Hello,\n\n"
                    + "This is an example of internationalized email body text. It includes non-ASCII characters like مرحبًا,ሀሎ,ආයුබෝවන්, 你好 (Arabic, Ethiopic, Sinhala and Chinese for \"Hello\").\n"
                    + "Feel free to add more internationalized content as you like.\n\n"
                    + "Best regards,\n"
                    + "Your Name\n";
            bodyPart.setText(messageText, "utf-8");

            // Create a Multipart object and add the MimeBodyPart to it
            Multipart multipart = new MimeMultipart();
            multipart.addBodyPart(bodyPart);

            // Set the content of the message to the Multipart object
            message.setContent(multipart);

            // Send the email
            Transport.send(message);
            System.out.println("Email sent successfully.");
        } catch (Exception e) {
            System.out.println("Email sending failed: " + e.getMessage());
        }
    }
}

## Understanding Multilingual Mailboxes: Parsing Internationalized Email Addresses

Parsing internationalized email addresses involves correctly extracting the local part (username) and domain part of an email address that may contain non-ASCII characters. 
The following are key points to consider while parsing internationalized email addresses:

<div class="obs-card">

<details>
<summary>Split the Email Address:</summary>

Split the email address into two parts: the local part and the domain part. The local part is the portion before the "@" symbol, and the domain part is the portion after the "@" symbol. For example, if the email address is "تجربة-بريد-الكتروني@تجربة-القبول-الشامل.موريتاني", splitting it would result in the local part "تجربة-القبول" and the domain part "تجربة-القبول-الشامل.موريتاني".

</details>

<details>
<summary>Decode the Domain Part:</summary>

If the domain part contains non-ASCII characters, it may be encoded using Punycode or UTF-8.
If the domain part is encoded with Punycode, you can use a Punycode decoder to convert it back to Unicode.
If the domain part is encoded with UTF-8, you may need to decode it using appropriate encoding/decoding functions.

</details>

<details>
<summary>Decode the Local Part:</summary>

The local part of the email address may also contain non-ASCII characters.
Check if the local part is encoded using any specific encoding scheme (e.g., UTF-8).
If encoded, apply the appropriate decoding method to convert it back to Unicode.

</details>

<details>
<summary>Validate the Email Address:</summary>

After decoding the local and domain parts, validate that they conform to the necessary requirements for email addresses.
Ensure that the email address follows the correct syntax, including the presence of the "@" symbol and a valid domain structure.
Apply any additional validation rules specific to your application or business logic.

</details>

</div>

It's important to note that email address parsing and handling can be complex due to the various standards, encoding schemes, and local rules that apply. To simplify the process, consider using established email parsing libraries or APIs that support internationalized email addresses, such as the `javax.mail.internet.InternetAddress` class in `JavaMail` or third-party libraries like the `email` module in Python.

These libraries often provide built-in functions for parsing, validating, and handling internationalized email addresses, taking care of the intricacies and edge cases involved in the process.

For instance, when validating email address length, consider the following factors:

<details>
<summary>Ensure that the length of the email address is within acceptable limits:</summary>

The maximum length of the entire email address (including the local part, domain part, and "@" symbol) is typically 254 characters according to the RFC 5321 specification.

</details>

<details>
<summary>Additionally:</summary>

Validate that the length of the local part does not exceed 64 characters, and the length of the domain part (after decoding) does not exceed 255 characters.

</details>

            return False

<details>
<summary>Character Encoding:</summary>

EAI allows the use of non-ASCII characters in the local part (username) of an email address. When setting up mailbox names, ensure that the character encoding used is compatible with EAI. Common encoding schemes for EAI include UTF-8, UTF-16, and MIME-encoded words. Choose an encoding scheme that is widely supported and compatible with your email server or service.

</details>

<details>
<summary>Punycode Encoding:</summary>

If your email system or server requires Punycode encoding for the domain part of the email address, ensure that the encoding is correctly applied. Punycode encoding is used to represent non-ASCII characters in the domain part using ASCII characters. Use a Punycode encoder library or built-in functions to encode the domain part when necessary.
