class Node:
    def __init__(self, value):
        self.value = value
        self.left = None
        self.right = None

def insert(root, value):
    if root is None:
        return Node(value)
    if value < root.value:
        root.left = insert(root.left, value)
    elif value > root.value:
        root.right = insert(root.right, value)
    return root

## Unicode Collation Algorithm for Sorting of Unicode Strings

<div class="info-card">

The Unicode Collation Algorithm (<span class="hl">UCA</span>) is a set of rules defined by the Unicode Consortium for sorting Unicode strings [<span class="hl">1</span>]. It provides a standard way to compare and order strings across different languages, scripts, and character sets.

The UCA defines a set of comparison rules that take into account various aspects of characters, including their code points, diacritics, case sensitivity, and linguistic context. These rules ensure that strings are sorted in a linguistically appropriate manner, respecting the language-specific sorting conventions.

</div>

The following are some key concepts and components of the Unicode Collation Algorithm:

<details>
<summary>Code Point Comparison:</summary>

The UCA primarily compares characters based on their Unicode code points. Code points are unique numerical values assigned to each character in the Unicode standard.

</details>

<details>
<summary>Diacritic Sensitivity:</summary>

The UCA considers diacritics (accent marks, tone marks, etc.) when comparing and sorting strings. It can distinguish between characters with and without diacritics, treating them as separate entities for sorting purposes.

</details>

<details>
<summary>Case Sensitivity:</summary>

The UCA can handle case-sensitive and case-insensitive sorting. It provides options to specify whether uppercase and lowercase letters should be treated as equivalent or distinct during the sorting process.

</details>

<details>
<summary>Linguistic Context:</summary>

The UCA takes into account the linguistic context of characters when determining their sorting order. Some characters may have different sorting rules depending on their position within a word or their relationship to surrounding characters.

</details>

<details>
<summary>Collation Elements:</summary>

The UCA breaks down strings into smaller units called collation elements. Collation elements represent individual characters or groups of characters with similar sorting properties. These elements are compared and ordered to determine the overall sorting order of the string.

</details>

<details>
<summary>Collation Rules:</summary>

The UCA defines a set of collation rules that specify the order of collation elements. These rules are language-independent and cover a wide range of characters, including Latin, non-Latin scripts, symbols, and punctuation.

</details>

Implementing the complete Unicode Collation Algorithm from scratch can be complex. However, most programming languages and frameworks provide built-in functions or libraries that implement the UCA for sorting Unicode strings. These functions typically leverage the Unicode character properties and collation data provided by the Unicode Consortium.

To sort strings using the Unicode Collation Algorithm (UCA), you can leverage the collation functionality provided by various programming languages and libraries.

<details>
<summary>How to Sort Strings Using the Unicode Collation Algorithm (UCA):</summary>

<details>
<summary>Choose a UCA-compliant Collation:</summary>

Check if your programming language or library supports UCA-compliant collations. Most modern programming languages have built-in support for Unicode collation. For example, in Java, you can use the Collator class with a UCA-compliant collation and the <span class="hl">pyuca</span> library provides an implementation of the Unicode Collation Algorithm (UCA) for Python.

</details>

<details>
<summary>Instantiate the Collator:</summary>

Create an instance of the collator for the desired locale or language. Specify the desired collation strength, such as primary, secondary, or tertiary level, depending on your sorting requirements. The collation strength determines the level of differentiation in sorting, such as considering case, accents, or diacritics.

</details>

## Techniques for Sorting and Searching Local Language Strings within Data Structures

When sorting and searching local language strings within data structures, several techniques can be employed to ensure accurate and efficient operations. Here are some commonly used techniques:

<details>
<summary>Unicode Collation:</summary>

Utilize Unicode collation algorithms that provide language-specific sorting rules. These algorithms consider linguistic and cultural conventions to determine the correct order of characters and strings. This ensures that sorting is performed in a manner consistent with the expectations of the specific language or locale.

</details>

<details>
<summary>Normalization:</summary>

Apply Unicode normalization forms, such as Normalization Form C (NFC) or Normalization Form D (NFD), to ensure that strings are represented in a standardized form. Normalization helps eliminate variations in character encoding and composition, allowing for consistent and accurate sorting and searching.

</details>

<details>
<summary>Comparison Functions:</summary>

Implement custom comparison functions that take into account the specific sorting rules and collation requirements of the language. These functions should consider linguistic factors such as accent marks, diacritics, case sensitivity, and language-specific sorting conventions.

</details>

<details>
<summary>Indexing and Search Algorithms:</summary>

Utilize indexing techniques like suffix arrays, tries, or ternary search trees to efficiently search for local language strings within data structures. These data structures allow for fast lookup and retrieval of strings based on prefixes, substrings, or complete words.

</details>

<details>
<summary>Binary Search:</summary>

If the data structure supports random access, employ binary search algorithms to locate specific local language strings efficiently. Binary search takes advantage of sorted order to quickly narrow down the search space and locate the desired string.

</details>

<details>
<summary>Language-Specific Libraries:</summary>

Make use of specialized libraries or frameworks that provide sorting and searching functionality tailored to specific languages or locales. These libraries often incorporate language-specific collation rules and optimized algorithms for efficient string manipulation.

</details>

<details>
<summary>Locale Settings:</summary>

Consider the locale settings of the application or system to ensure that appropriate language-specific sorting and searching rules are applied. The locale settings define the language, country, and cultural conventions, which can impact the sorting order of local language strings.

</details>

By employing these techniques, developers can ensure accurate sorting and efficient searching of local language strings within data structures, accommodating the linguistic requirements and cultural conventions specific to each language or locale.

import java.text.Normalizer;
import java.util.Arrays;

public class UStringTimSorter {
    public static int compareStrings(String str1, String str2) {
        String str1Norm = Normalizer.normalize(str1, Normalizer.Form.NFD);
        String str2Norm = Normalizer.normalize(str2, Normalizer.Form.NFD);
        return Character.compare(str1Norm.charAt(0), str2Norm.charAt(0));
    }

    public static void insertionSort(String[] arr, int left, int right) {
        for (int i = left + 1; i <= right; i++) {
            String key = arr[i];
            int j = i - 1;
            while (j >= left && compareStrings(arr[j], key) > 0) {
                arr[j + 1] = arr[j]; j--;
            }
            arr[j + 1] = key;
        }
    }

    public static void merge(String[] arr, int left, int mid, int right) {
        String[] leftArr  = Arrays.copyOfRange(arr, left, mid + 1);
        String[] rightArr = Arrays.copyOfRange(arr, mid + 1, right + 1);
        int i = 0, j = 0, k = left;
        while (i < leftArr.length && j < rightArr.length) {
            if (compareStrings(leftArr[i], rightArr[j]) <= 0) arr[k++] = leftArr[i++];
            else arr[k++] = rightArr[j++];
        }
        while (i < leftArr.length)  arr[k++] = leftArr[i++];
        while (j < rightArr.length) arr[k++] = rightArr[j++];
    }

    public static String[] timSort(String[] arr) {
        int n = arr.length, minRun = 32;
        for (int i = 0; i < n; i += minRun)
            insertionSort(arr, i, Math.min(i + minRun - 1, n - 1));
        for (int size = minRun; size < n; size *= 2) {
            for (int start = 0; start < n; start += size * 2) {
                int mid = Math.min(start + size - 1, n - 1);
                int end = Math.min(start + size * 2 - 1, n - 1);
                merge(arr, start, mid, end);
            }
        }
        return arr;
    }
}

import java.util.Arrays;

public class LexicographicBinarySearch {
    public static int binarySearchUnicode(String[] arr, String target) {
        int low  = 0;
        int high = arr.length - 1;
        while (low <= high) {
            int mid    = (low + high) / 2;
            String midVal = arr[mid];
            if (target.equals(midVal)) {
                return mid;
            } else if (target.compareTo(midVal) < 0) {
                high = mid - 1;
            } else {
                low = mid + 1;
            }
        }
        return -1; // Target not found
    }

## Searching Through Unicode Text (Normalization + Collation)

When searching through Unicode data, it's important to consider both normalization and collation to ensure accurate and effective matching. Below is a summary of how normalization and collation can be applied during Unicode data searching:

<details>
<summary>Normalization:</summary>

- Unicode normalization involves transforming Unicode strings into a standardized form that eliminates any variations in character representation. This helps ensure that equivalent strings are treated as identical during searching. The most commonly used normalization forms are NFC (Normalization Form Canonical Composition) and NFD (Normalization Form Canonical Decomposition).
- To apply normalization during searching, you need to normalize both the search query and the data being searched. This ensures that any differences in character representation, such as combining characters or different composition forms, are accounted for and matched correctly.

</details>

<details>
<summary>Collation:</summary>

- Collation is the process of ordering strings based on a predefined set of rules or a collation algorithm. When searching through Unicode data, you want to ensure that the collation order used during sorting is also applied during searching. This ensures consistent and accurate matching based on the linguistic and cultural expectations of the data.
- To perform collation-based searching, you need to use a collator that supports the desired collation algorithm, such as the Unicode Collation Algorithm (UCA). The collator takes into account language-specific rules, diacritic sensitivity, case sensitivity, and other aspects to determine the correct sorting and matching order.

</details>

    return unicodedata.normalize('NFC', text).lower()

import java.text.Collator;
import java.text.Normalizer;
import java.util.Locale;

public class StringSearchExample {
    public static void main(String[] args) {
        String[] strings = {
            "সর্বজনীন-স্বীকৃ তির-পরীক্ষা.ভারি",    // Bangla (Bengali)
            "универсальное-принятие-тест.москва",       // Cyrillic
            "सार्वभौमिक-स्र्ीकृति-परीक्षण.संगठन",    // Devanagari
            "უნივერსალური-თავსობადობის-ტესტი.გე",      // Georgian
            "καθολική-αποδοχή-δοκιμή.ευ",              // Greek
            "تجربة-القبول-الشامل.موريتانيا",            // Arabic
            "普遍适用测试.我爱你",                         // Simplified Chinese
            "ඉ-තැපැල්-පිරික්සුම@විශ්ව-සම්මුති-පිරික්සුම.ලංකා" // Sinhala
        };

        String searchQuery = "καθολικη-αποδοχη-δοκιμη.ευ"; // Designated search query
        // Normalize the search query using Unicode normalization form NFD
        String normalizedSearchQuery = Normalizer.normalize(searchQuery, Normalizer.Form.NFD);
        // Create a Collator instance for the default locale with strength PRIMARY
        Collator collator = Collator.getInstance(Locale.getDefault());
        collator.setStrength(Collator.PRIMARY);
        boolean found = false;
        for (String str : strings) {
            String normalizedStr = Normalizer.normalize(str, Normalizer.Form.NFD);
            if (collator.compare(normalizedSearchQuery, normalizedStr) == 0) {
                found = true;
                break;
            }
        }
        if (found) {
            System.out.println("Search text " + searchQuery + " is found in the array.");
        } else {
            System.out.println("Search text " + searchQuery + " is not found in the array.");
        }
    }
}
